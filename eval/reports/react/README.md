# ReAct 文档评测档案

评测对象为《ReAct: Synergizing Reasoning and Acting in Language Models》的英文原文及中文机器翻译版。语料位于项目根目录的 `ReAct.pdf` 和 `doc.pdf`。本档案集中记录 2026-11-04 至 2026-11-05 的开发评测及更早的检索基线信息。

## 评测流程与工具分工

系统一次问答的处理流程如下。

```text
用户问题 → 检索相关片段 → 精排与片段选择 → 将资料交给 DeepSeek → 最终回答
```

评测覆盖其中两个层次。检索评测检查能否找到答案证据，以及证据排在什么位置。回答评测继续调用生成模型，检查最终答案是否完整、是否有片段依据，以及资料不足时如何处理。

项目原来已有 `eval/run_eval.py` 和中英各 22 道检索题。本目录的“早期检索基线与标注说明”来自原 `eval/README.md`，记录这套已有评测的指标、结果和标注局限。后续接入 promptfoo，增加了批量调用问答接口、检查最终回答、对照方案以及调用评分模型的流程。

| 工作 | 本项目中的执行方 | 产出 |
|---|---|---|
| 标记答案证据、定义参考答案和检查规则 | 项目题库及评测代码，包含 AI 起草与复核 | 标注块、参考答案、评分标准 |
| 计算 44 道检索题的召回、精排及上下文指标 | Python 检索评测脚本 | 检索基线和策略对照表 |
| 批量调用 `/ask`、收集答案、执行规则并保存结果 | promptfoo | 首批端到端结果和检索方案的问答对照 |
| 根据资料生成用户答案 | DeepSeek 与项目 RAG 管道 | 报告中的实际回答 |
| 按语义标准评分 | DeepSeek 评分模型，由 promptfoo 组织调用 | 正确性、依据一致性、证据边界和语言评分 |
| 实现 BM25 融合、相邻块补充等改进 | 项目检索代码 | 供评测比较的检索方案 |

例如，问题“论文用了哪四个基准？”的中文证据跨第 13、14 块。原检索指标找到任一标注块即可计为命中，最终回答仍可能漏掉 WebShop。新增的回答检查要求四个名称完整出现，从而识别这种“找到相关资料但答案仍不完整”的情况。

## 报告阅读顺序

1. **早期检索基线**记录原来已有的找资料能力。
2. **首批端到端基线**通过完整问答流程检查最初的回答质量。
3. **检索策略对照**比较不同找资料方式对证据覆盖和最终回答的影响。
4. **AI 证据复核表**对已保存的 20 道回答逐项给出参考评分。
5. **语义评估与提示词对照**使用相同片段比较提示词，并检查评分模型的分歧和漏判。

“基线”表示用于比较的原方案及其结果。“候选”表示实验中的改进方案。检索对照中的候选后来被采用为默认检索配置；提示词实验的默认配置仍为 legacy。两个实验阶段各自有明确的比较对象。

## 结果记录

- 检索阶段采用中文融合检索、英文向量检索及有预算的相邻块扩充。原提示词下的端到端规则检查由 15/20 提高到 18/20。
- 提示词候选改善了回答语言与证据不足处理，但出现补全缺损姓名、机构编号误读和项目编号转金额。当前服务默认提示词为 legacy。
- 英文作者机构与中文受控比较两题仍缺少关键检索证据。合理拒答的行为评分与原文事实答案的完成情况分别记录。
- 参考复核由 AI 完成，独立人工复核待完成。模型裁判存在漏判，多轮提示词实验使用了同一批开发题。
