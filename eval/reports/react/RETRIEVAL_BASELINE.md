# 检索质量评测集

## 报告来源与范围

本报告整理自项目原有的 `eval/README.md`，对应 `eval/run_eval.py` 及中英各 22 道检索题，属于接入 promptfoo 之前已有的评测。这里检查问题能否检索到预先标记的答案证据，生成模型的最终回答在后续端到端评测中检查。

“标注块”是题库中预先标记为包含答案相关证据的文本块。例如，某题的证据块为第 13、14 块，检索结果包含其中任意一块时，该题的任一块命中指标记为成功。若完整答案需要两块共同提供信息，命中其中一块仍可能只覆盖部分答案。

本报告中的基线用于记录修改前的检索水平。后续完整问答的结果见 [首批端到端评测](BASELINE.md)，检索改进的收益与退步见 [检索策略对照](RETRIEVAL_COMPARISON.md)。

当前默认使用按语种选择的检索策略及相邻块扩充。开启扩充时，脚本输出 `Hit@Ctx`，MRR 按最终上下文顺序计算。复现下方 2026-10-01 向量检索基线，需要设置 `RETRIEVAL_MODE=vector`、`CONTEXT_NEIGHBORS=0`。包含精排种子指标与上下文指标的对照见 [检索策略报告](RETRIEVAL_COMPARISON.md)。

只评**检索**，不调 LLM——生成质量是另一回事，而且一旦调 LLM，评测就变慢、变贵、
不可复现。调参时需要的是一条稳定的基线。

## 怎么跑

```bash
python eval/run_eval.py            # 两个库都跑
python eval/run_eval.py zh         # 只跑中文库
python eval/run_eval.py en -v      # 只跑英文库，并打印逐题明细
```

不需要 Redis、不需要 DeepSeek Key。要加载 embedding 模型和 cross-encoder
（首次约 20 秒），所以比 `verify_cache.py` 慢，但完全离线。

## 三个指标分别回答什么

| 指标 | 含义 | 低了说明什么 |
|---|---|---|
| **Recall@K** | 召回阶段（k=RETRIEVE_K）捞到标准答案了吗 | 没捞到 → 问题在**向量检索或切块**，跟精排无关，改精排没用 |
| **Hit@N** | 精排后的 top_n 里有吗 | 召回捞到了这里却没有 → 问题在 **cross-encoder 精排** |
| **MRR** | 第一个命中的名次倒数 | 衡量排序质量，比 Hit 更细腻 |

把"召回没捞到"和"精排排掉"分开统计是刻意的：两者的修法完全不同，
混在一起看只会得出"检索不行"这种没法行动的结论。

## 基线（2026-10-01，CHUNK_TOKENS=256 / overlap=40）

```
库       块数   题数   Recall@K   Hit@N     MRR
zh       173     22     59.1%     54.5%    0.413
en       136     22     95.5%     86.4%    0.725
```

**中文库明显更差**，10 道未命中里 8 道是"召回阶段就没捞到"。初步归因：

1. **译文用词与自然中文提问对不上**。语料是机器翻译的中文版，
   例如问"大语言模型"，而目标块里只有 `PaLM`（"语言模型"这个词压根没出现）。
2. **中文模型区分度更弱**。实测 top1 与 top20 的余弦差距：中文 0.080、英文 0.127。
   另一个可能原因是 `text2vec-base-chinese` 是通用句子相似度模型，
   并非为"短查询 → 长段落"这种非对称检索训练（bge 系列是）。

下一步值得试的：换 `BAAI/bge-base-zh-v1.5` 或 `bge-m3`，然后用这个评测集量化提升。

## ⚠️ 已知的语料缺陷

`ReAct.pdf` 有 **15 个块（约 11%）是坏编码文本**——PDF 字体的 ToUnicode 映射
损坏，PyMuPDF 抽出来的字被整体位移了（如 `QFDELQHW` 对应 `cabinets` 一类）。
块号 `[4-10, 65-68, 71-74]`。

这些块**不能作为标准答案**（本题库已避开），但它们仍在库里参与检索，
会产生无意义的向量并可能挤占召回名额。要根治需要换抽取方式（pdfplumber /
OCR / 换 PDF 来源）。

## 关于标注

- **块号与切块参数绑定**。改 `CHUNK_TOKENS` / `CHUNK_OVERLAP_TOKENS` 后块号会变，
  必须重新标注。`run_eval.py` 会在标注越界时直接报错，不会给出假分数。
- **每题可以有多个标准答案块**。答案分散在不同章节时（如 `en-21`/`zh-21`），
  只标一块会低估检索效果。
- **`hard` 类题目是刻意设计的低字面重叠题**，用来测语义召回能力；
  它们不命中不代表系统坏了，但要盯住别退步。
- **这些标注是 AI 起草的，需要人工复核。** 每题的 `why` 字段写了为什么标这块，
  复核时直接对照 `chunks_preview_{lang}.md` 看即可。
