# Redis 实现教程 —— 以本项目的缓存层为例

这套教程讲的是**你这个项目里真实存在的 Redis 代码**（`cache.py` + `tools/`），
不是泛泛的 Redis 入门。每一节都会指到具体文件和行号，你可以对着源码读。

## 为什么拿这个项目当教材

大多数 Redis 教程停在"`SET` / `GET` / 过期时间"这一层。但你这个项目里有几样**很少见**的东西：

1. **手写的 RESP 协议客户端和服务端**（`tools/resp_client.py`、`tools/mini_redis_resp.py`）
   —— 大部分人用了一辈子 Redis 也没看过协议长什么样，这里你有一条完整的、只有 130 行的实现可以读。
2. **一套完整的"降级"设计**（Redis 连不上自动退回内存，且不改变正确性）
   —— 这是缓存系统设计的核心问题，比 API 用法重要得多。
3. **生产级的取舍痕迹**：为什么用 `SCAN` 不用 `KEYS`、为什么要强制 RESP2、
   为什么版本号不能设过期、为什么缓存异常必须 fail-open。每一条都有注释解释**为什么**。
4. **三个真实存在的 bug**（第 6 节），其中一个连"接口模仿 redis-py"这句注释都被推翻了。

## 三个必须记住的结论

如果只想记三句话：

1. **缓存是加速层，不是数据源。** 任何一次缓存异常都应该回落真实计算（fail-open），
   "变慢"可以接受，"变错"不可以。
2. **失效比写入难。** 写入错了只是没缓存上，失效错了会让用户拿到**看起来正常但其实错误**的答案。
   本项目用"版本号 + key 前缀"解决，见第 5 节。
3. **接口像 ≠ 协议兼容。** 项目里那个"刻意模仿 redis-py"的客户端，
   因为一个命令名写错（`DELETE` vs `DEL`），实际**无法和真实 Redis 通信**。见第 6 节。
